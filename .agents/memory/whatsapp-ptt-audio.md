name: WhatsApp PTT audio
description: Evolution API behavior for sending prerecorded WhatsApp voice notes.
---

For outgoing WhatsApp voice notes, Evolution's `sendWhatsAppAudio` endpoint sends PTT media. The business expects a 30-second recording presence before delivery; this is intentional despite the added wait. For the first bronze question in a conversation, send the AI's short text intro, try the bronze audio once, then explain the confirmed difference: natural bronze uses solar exposure; machine bronze uses WB Ultra (72 lamps, about 8–20 minutes according to phototype, with individualized service). Do not repeat the clip after a successful send, and still send the text explanation if audio delivery fails. With encoding enabled, Evolution converts the source audio to OGG/Opus for WhatsApp; the original asset can remain unchanged.

**Why:** WhatsApp PTT expects a voice-note-compatible codec, while uploaded recordings may be OGG/Vorbis. Sending ordinary audio media does not provide the same voice-note presentation, and omitting the delay skips the visible recording presence. The 30-second duration was explicitly requested to make the recording indicator last longer, so the HTTP timeout must also exceed the recording delay. The user also requested an early bronze audio followed by a method comparison, and confirmed that natural bronze uses solar exposure.

**How to apply:** Send the original asset as base64 through Evolution's voice-audio endpoint with encoding enabled and a 30-second delay; set the provider request timeout to at least the recording delay plus network headroom. For the first bronze inquiry, deliver a short intro before the audio and the method comparison afterward. Keep audio delivery best-effort so its failure does not suppress the text answer. Use the provider's conversion rather than replacing or re-encoding the stored user asset.
