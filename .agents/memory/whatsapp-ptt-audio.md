For outgoing WhatsApp voice notes, Evolution's `sendWhatsAppAudio` endpoint sends PTT media. The business expects a 30-second recording presence before delivery; this is intentional despite the added wait. For the first bronze question in a conversation, send the AI's short text intro, try the bronze audio once, then explain the confirmed difference: natural bronze uses solar exposure; machine bronze uses WB Ultra (72 lamps, about 8–20 minutes according to phototype, with individualized service). Track attempts separately for each prerecorded clip and never replay the same clip in the conversation, including after pending or failed attempts; this prevents duplicate audio without suppressing a relevant first-time clip. Still send the text explanation if audio delivery fails. With encoding enabled, Evolution converts the source audio to OGG/Opus for WhatsApp; the original asset can remain unchanged.

**Why:** WhatsApp PTT expects a voice-note-compatible codec, while uploaded recordings may be OGG/Vorbis. Sending ordinary audio media does not provide the same voice-note presentation, and omitting the delay skips the visible recording presence. The 30-second duration was explicitly requested to make the recording indicator last longer, so the HTTP timeout must also exceed the recording delay. The user also requested an early bronze audio followed by a method comparison, confirmed that natural bronze uses solar exposure, and clarified that the problem is repeating the same clip in one conversation, not sending a relevant clip without a separate request.

**How to apply:** Send the original asset as base64 through Evolution's voice-audio endpoint with encoding enabled and a 30-second delay; set the provider request timeout to at least the recording delay plus network headroom. For the first bronze inquiry, deliver a short intro before the audio and the method comparison afterward. Track persisted attempts—not only successful deliveries—per clip to avoid replaying that same recording, while keeping its failure from suppressing the text answer or a distinct relevant clip. Use the provider's conversion rather than replacing or re-encoding the stored user asset.
